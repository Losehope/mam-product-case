# MAM 产品原型（可运行 demo）

> 0 依赖、单进程、一条命令启动。用水把**产品规则**跑一遍，而不是展示技术栈。

```bash
cd demo
python3 app.py
# 打开 http://localhost:8000
```

- 需要 Python 3.8+，**不需要** pip install、不需要数据库、不需要 Node。
- 每次启动重建 `demo.db`，演示状态可预期；`Ctrl+C` 退出。
- 端口占用时：`PORT=8080 python3 app.py`。

> 真实系统是 Spring Boot + Vue + 微信小程序（见仓库根目录案例）。
> 这里的实现刻意简化了技术栈，**只保留值得被验证的产品规则**。

## 1. 五分钟演示剧本

按顺序切换右上角身份，就能把整条链路走完。

| 步骤 | 身份 | 操作 | 想让你看到什么 |
|---|---|---|---|
| 1 | 北站观影团 | 看项目广场 | 没有准入资格，只看得到**公开项目** |
| 2 | 城南观影团 | 看项目广场 | 多出一个**仅准入**项目；私密项目不在广场 |
| 3 | 城南观影团 | 点「填写申请表」 | 团名、城市、影城、收件信息**自动预填** |
| 4 | 星幕影厅（渠道） | 申请审核 → 通过 | 状态从待审核变为已通过 |
| 5 | 星幕影厅 | 批量发货 → 填单号 → 预览 | 先预览再确认；**预览后改数据会被整批拒绝** |
| 6 | 城南观影团 | 返图与流团 → 提交返图 | 返图字段由渠道方在项目里配置 |
| 7 | 星幕影厅 | 返图评分 → 评分 | 申请归档为已完成，进入历史评分 |
| 8 | 平台管理员 | 认证审核 | 认证是唯一的授权入口 |

**验证「整批停止」**：在步骤 5 点「预览」后，另开一个标签页用渠道身份把其中一条申请驳回或改数量，再回来点「确认发货」——会返回 409，整批不动。

**验证「私密项目」**：项目广场顶部有「演示辅助：私密项目分享入口」，填入 `demo-share-001` 后，城市限定票根会出现。凭证错误则不出现。

**验证「驳回重提」**：城南团长的「我的申请」里有一条已驳回记录，点「修改重提」，轮次从 v1 变成 v2，审核备注被清空。

## 3. 代码结构

```
demo/
├── app.py          # 路由 + 业务规则 + HTTP 服务（约 500 行）
├── db.py           # 建表 + 种子数据（30 秒就能看懂的数据模型）
├── web/
│   ├── index.html
│   ├── app.js      # 原生 JS，无构建
│   └── style.css
└── demo.db         # 启动时自动生成，已 gitignore
```

数据模型只有 6 张表：`users` `channels` `groups` `admissions` `projects` `applications`（外加 `certs`）。

## 4. 以下为有意不做

- **登录与密码**：用 `X-Demo-User` 头模拟身份，右上角切换。
- **角色的动态授予**：认证审核只改状态，不真的写入角色（真实系统在这里同步档案）。
- **真实物流、短信、图片识别、订阅消息**：全部不在原型范围内。
- **并发与事务的真实强度**：快照与指纹是真实逻辑，但没有做数据库行锁与连接池压测。
- **权限的完整覆盖**：只覆盖了演示路径上的关键边界（越权审核、越权发货、无准入申请、重复发货）。

**这个原型证明的是规则能跑通，不是系统能上线。**

## 5. 调试参数

| 参数 | 作用 |
|---|---|
| `?user=5` | 指定初始身份（1 影迷 / 2-4 观影团 / 5-6 渠道方 / 7 管理员） |
| `?tab=review` | 指定初始页签 |
| `?share=demo-share-001` | 模拟打开私密项目的分享链接 |
| `?apply=1` | 直接打开某个项目的申请表（便于截图） |
